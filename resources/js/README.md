# Frontend

React 19 + Inertia, served by Laravel. Plain JavaScript — no TypeScript. Every import uses the `@/` alias, which
points at this folder (`resources/js/`). There are no `../../..` imports —
please keep it that way.

```
resources/js/
├─ app.jsx              # entry point: Inertia setup, layout routing, theme
├─ pages/               # one file per Inertia page — keep these thin
│  ├─ welcome.jsx       #   /            (home)
│  ├─ services.jsx      #   /services
│  ├─ philosophy.jsx    #   /philosophy
│  └─ contact.jsx       #   /contact
├─ features/            # ← your clinic code goes here, one folder per page
│  ├─ home/
│  ├─ services/
│  ├─ philosophy/
│  └─ contact/
├─ shared/              # reused across features
│  ├─ content/site.ts   # clinic name, nav links, footer links
│  ├─ components/
│  │  ├─ app/           # dashboard shell, sidebar, nav, user menu
│  │  ├─ auth/          # passkeys, two-factor, delete account
│  │  ├─ common/        # heading, text-link, input-error, password-input
│  │  └─ marketing/     # page-heading (public pages)
│  ├─ hooks/            # use-appearance, use-current-url, use-mobile...
│  └─ lib/              # utils.ts (the `cn` helper)
├─ components/ui/       # shadcn/ui primitives — generated, don't hand-edit
├─ layouts/
│  ├─ marketing-layout.jsx  # header + footer for the public pages
│  ├─ marketing/            #   site-header, site-footer
│  ├─ app-layout.jsx        # signed-in dashboard
│  └─ auth-layout.jsx
```

## Where do I put this?

| I'm building...                      | Put it in                   |
| ------------------------------------ | --------------------------- |
| A band of the clinic homepage        | `features/home/sections/`   |
| A piece used by one homepage section | `features/home/components/` |
| Something two features both need     | `shared/components/common/` |
| A new page the router points at      | `pages/`                    |
| A generic button/dialog/input        | `npx shadcn@latest add ...` |

See [features/README.md](./features/README.md) for the full convention.

## Folders you shouldn't reorganize

Three folders have their paths hard-coded elsewhere. Moving them breaks the
build:

- **`pages/`** — every public page also needs its name listed in
  `MARKETING_PAGES` in `app.jsx`, or it will render inside the signed-in
  dashboard shell instead of the marketing header/footer.
  `resources/views/app.blade.php` loads pages by convention
  (`resources/js/pages/{component}.jsx`), and Inertia resolves page names
  against this folder. A page named `settings/profile` _must_ live at
  `pages/settings/profile.jsx`.
- **`components/ui/`** — `components.json` points shadcn here, and
  `vite.config.ts` excludes it from lint and formatting because the files are
  generated.
- **`routes/`, `actions/`, `wayfinder/`** — these don't exist in the repo. They
  are generated by the Wayfinder Vite plugin when you run `npm run dev` or
  `npm run build`, which is what makes `import { login } from '@/routes'`
  work. Never create or edit them by hand.

## Commands

```bash
npm run dev           # vite dev server (also generates the route helpers)
npm run build         # production build
npm run check         # lint
npm run check:fix     # lint + autofix
npm run types:check   # tsc --noEmit
```

## JavaScript

Plain `.jsx` / `.js` — there is no build-time type checking, so nothing stops
you passing the wrong prop. Two habits keep that manageable:

- Destructure props in the signature, so a component's inputs are visible at
  a glance:

```jsx
export default function DoctorCard({ name, specialty }) { ... }
```

- Keep data in the feature's `content.js` rather than inline, so shape
  changes happen in one place.

Editor autocomplete for the `@/` alias comes from `jsconfig.json` in the
project root.

### The one place TypeScript remains

`resources/js/routes/`, `resources/js/actions/`, and `resources/js/wayfinder/`
are `.ts` files, because the Wayfinder Vite plugin generates them that way and
regenerates them on every `npm run dev` / `npm run build`. Vite compiles them
fine and you never edit them by hand, so they are excluded from linting and
formatting. Leave them alone.
